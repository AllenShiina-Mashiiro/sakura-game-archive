# v2.6-dev 本地 PostgreSQL / Drizzle

## 安装依赖

拉取 `v2.6-dev` 后，在项目根目录运行一次 `npm install`。这会安装 Drizzle / PostgreSQL 驱动，并同步更新 `package-lock.json`；之后常规安装继续使用 `npm ci`。

## 本地连接

Docker PostgreSQL 已运行时，在项目根目录创建 `.env.local`（不要提交）：

```dotenv
DATABASE_URL=postgresql://sakura_admin:<你的本地数据库密码>@127.0.0.1:5432/sakura_game_archive
SESSION_SECRET=<至少32位随机字符串>
```

Drizzle 连接入口为 `lib/postgres.ts`，数据表定义为 `drizzle/schema.ts`。

## 从当前单独运行的数据库容器切换到 Compose

如果你目前已经有名为 `sakura-game-archive-db` 的独立容器，切换 Compose 前先保留数据卷，只停止并移除容器：

```powershell
docker stop sakura-game-archive-db
docker rm sakura-game-archive-db
```

Compose 会重新使用名为 `sakura-game-archive` 的现有数据卷，不要执行 `docker volume rm` 或 `docker compose down -v`。

## 初始化认证基础表

当前迁移文件建立认证基础表；其余业务关系表由 Drizzle Kit 根据 `drizzle/schema.ts` 生成后续迁移。不导入旧 Supabase `app_state` 数据，也不会删除或修改云端 Supabase 数据。

确认连接字符串指向本机 Docker 数据库后，在 PowerShell 执行：

```powershell
Get-Content .\drizzle\migrations\0000_auth_foundation.sql | docker exec -i sakura-game-archive-db psql -U sakura_admin -d sakura_game_archive
```

## 当前迁移边界

此提交先建立 Drizzle 连接、用户/会话/验证码/OAuth 表结构。现有业务读写仍由旧 `lib/db.ts` 提供，认证 API 尚未切换；不要把本阶段误认为已经完成 Supabase 移除。后续需逐类迁移业务数据访问并完成验证后，才可移除旧 Supabase/Upstash 依赖。

邮箱验证码与 OAuth 的邮件服务、Google/GitHub OAuth 应用配置尚未接入。验证码只保存哈希，不保存明文。
