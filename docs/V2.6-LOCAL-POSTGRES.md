# V2.6-dev 本地 PostgreSQL / Docker

本分支以 Windows 本机 Docker Compose + PostgreSQL 作为开发与验收环境。现有页面和主要业务操作继续保留，业务数据由 PostgreSQL 关系表承载；不导入旧 JSON 文件或 Supabase app_state 业务数据。

## 1. 配置环境

复制 .env.example 为项目根目录的 .env，并填写：

- POSTGRES_PASSWORD：建议使用随机十六进制字符串，避免连接 URL 中出现需要转义的特殊字符。
- SESSION_SECRET：至少 32 位随机字符串。
- ADMIN_PASSWORD：初始管理员密码，至少 10 位。
- SMTP_HOST、SMTP_PORT、SMTP_USER、SMTP_PASSWORD、SMTP_FROM：邮箱验证码发送服务。
- GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET 和 GITHUB_CLIENT_ID / GITHUB_CLIENT_SECRET：按需配置第三方登录。
- AUTH_BASE_URL：本机为 http://localhost:3000；Ubuntu 远程测试时改为虚拟机可访问的地址或 HTTPS 域名。

本机直接运行 Next.js 时，再将相同数据库连接信息放进 .env.local，其中 DATABASE_URL 主机使用 127.0.0.1。Compose 中的应用容器会使用 Docker 网络服务名 postgres，无需使用宿主机地址。

## 2. 启动 PostgreSQL

```powershell
docker compose up -d postgres
docker compose ps
docker compose logs -f postgres
```

数据库服务名为 postgres，容器名为 sakura-game-archive-db，默认端口只绑定到本机 127.0.0.1:5432。

## 3. 执行数据库迁移

在项目根目录执行：

```powershell
npm install
npm run db:migrate
```

迁移文件按顺序建立认证、业务关系表和写入版本控制表。Drizzle 配置会读取本机 .env.local / .env 中的 DATABASE_URL。

如果 PostgreSQL 命名卷已经初始化，/docker-entrypoint-initdb.d 中新增的 SQL 不会自动重跑；此时仍然要执行 npm run db:migrate。不要随意执行 docker compose down -v，它会删除数据库卷。

## 4. 启动应用

本机开发：

```powershell
npm run dev
```

Docker 全栈：

```powershell
docker compose up -d --build
docker compose ps
docker compose logs -f sakura-game-archive
```

## 5. 邮箱验证码与 OAuth

注册使用六位数字邮箱验证码，有效期 10 分钟；用户名只输入小写字母、数字和下划线（3-24 位），页面公开展示为 @用户名。内部用户主键仍使用 UUID，确保外键关系稳定。

OAuth 回调路径：

- Google：/api/auth/oauth/google
- GitHub：/api/auth/oauth/github

本机开发者控制台登记完整 localhost 回调 URL。远程测试时将 AUTH_BASE_URL 改成虚拟机可访问的基础 URL，并在对应 OAuth 控制台登记匹配的完整回调 URL。OAuth 邮箱必须由服务商标记为已验证。

## 6. 当前边界

- 业务读写已切换到 PostgreSQL 关系表，旧 app_state 快照不再是运行时数据源。为保留现有页面和业务操作，本阶段通过事务兼容层读写关系表；每次业务变更会重写业务表集合。该方式便于本地功能迁移，但高频接口的增量写入、并发与性能仍需在正式部署前继续优化和验收。
- 注册验证码、Google/GitHub OAuth 代码已接入，但必须配置真实 SMTP / OAuth 凭据后才能完成端到端测试。
- 图片上传与历史图片 URL 仍保留 Supabase Storage 兼容逻辑；这不承担业务数据库职责，图片文件存储迁移尚未完成。
- Ubuntu 虚拟机迁移、反向代理/TLS、备份恢复和云服务器部署，均安排在 Windows 本机数据库迁移及业务回归通过之后。
